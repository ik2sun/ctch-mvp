# GEO 진단 프레임 (측정 → 재해석 → 전략)

핵심 명제: **"정보 노출은 누구나 하지만, 실제 답변이 되는 것은 다른 문제"**. 진단의 목적은 점수가 아니라 "AI가 실제로 무엇이라 답했는가"를 원문으로 확인하고, "어떤 질문에 답변이 되기를 원하는가"를 정의하는 것이다.

기준 사례: `knowledge/01_aestura_geo_report_2026-08.md`, `knowledge/02_aestura_qa_records_22xlsx.md` (프로젝트 루트). 새 대상 진단 시 이 두 문서의 구조를 재사용한다.

## 1단계. 대상·질문 설계

1. 대상 페이지 확정(구조화 데이터가 적용된 페이지 우선). 브랜드 사이트와 커머스몰이 분리되어 있으면 **둘 다 대상인지** 먼저 확인하고 범위를 명시한다.
2. 질문은 지어내지 않는다. 대상 페이지의 **JSON-LD(FAQ·Product·additionalProperty)·본문 문구**에서 직접 추출한다. 추출 근거(원문)를 질문마다 기록한다.
3. 전부 **비브랜드** 질문. 페이지당 2개 = 범용 조건 1(카테고리 일반 추천) + 고유 조건 1(페이지 고유 수치·성분·효능 검증형).
4. 여정 구간을 분산한다: 정보 탐색(지식 질문) / 대안 비교 / 문제 해결·검증 / 구매 직전. 상품 페이지에서만 뽑으면 **비교 의도(comparison)로 편중**되어 사이트가 가장 약한 영역만 측정하게 된다. 지식 질문을 별도로 최소 4개 추가한다.
5. 경쟁사 목록은 사전 등록하되, 실측 후 "AI가 실제로 호명한 브랜드"로 교정한다.

## 2단계. 다중 엔진 질의

- 엔진: ChatGPT · Gemini · Perplexity · Claude (+ 국내 대상이면 네이버 AI 브리핑·AI 탭, 필요 시 Copilot).
- **매 질의 세션 초기화**(대화 이력 없음). 자동 측정에서 유효 응답이 없는 엔진(ChatGPT 사례)은 로그아웃·시크릿·신규 세션으로 수동 질의해 보완하고 그 사실을 명시한다.
- 기록 항목: query_id, 질문 전문, 유형, 엔진, 언급 여부, 언급 순위, 감성, **응답 원문 전체**, 인용 URL 전수(순위 포함).
- 브랜드 인지 대조 실험: 미언급 질문 뒤에 "○○ 브랜드 제품은?" 한 문장을 추가 질의해 **읽기 가능 여부**와 **후보군 진입 실패**를 분리 증명한다.

## 3단계. 집계 매트릭스

| 지표 | 정의 |
|---|---|
| AI 언급 점유율 | 언급 응답 수 / 총 응답 수 |
| 1순위 추천 | 추천 목록 최상단 배치 수 (엔진별 분리) |
| 엔진별 언급률 | 엔진별 언급 / 질문 수 |
| 페이지(상품)별 언급률 | 페이지별 언급 / (질문 2 × 엔진 수) → 페이지 간 격차(배수) |
| 전 엔진 미언급 질문 | 어느 엔진에서도 나오지 않은 질문과 그 자리를 차지한 브랜드 |
| 경쟁사 동시 호명 | 등록 경쟁사별 동시 호명 수, 우위/미언급 |

주의: 브랜드명 매칭 집계는 제품명 단독 등장을 놓친다. 원문을 대조해 "집계 외 실질 노출"을 별도 표기한다. 실재 불확실 제품명(환각)도 언급으로 잡힐 수 있으니 표기한다.

## 4단계. 인용 출처 전수 분류

- 인용 URL을 질문 단위로 귀속해 전수 기록한다(날짜 단위 누적 집계와 섞지 않는다).
- 유형 분류: 자사 / 그룹(커머스몰) / 이커머스 / 뷰티·리뷰 플랫폼 / 블로그 / 영상 / 커뮤니티 / 미디어 / 학술·의료기관 / 기타.
- 산출 지표: 자사 도메인 인용 비중, 자사 인용 순위, 상위 도메인 20, 유형별 분포.
- **도달 경로 판정**: 자사 문구가 답변에 등장할 때 출처가 자사인지(직접 인용, 정확하지만 순위 낮음) 외부 채널인지(경유 인용, 순위 높음). 두 경로를 분리해 보고한다.
- 엔진별 인용 산출 여부를 명시한다(ChatGPT·Claude는 미산출이 흔함). 인용 로직은 `ai-engine-citation-logic` 참조.

## 5단계. 기술 진단 (별도 수행)

| 영역 | 점검 항목 |
|---|---|
| 크롤러 | 사이트맵 URL 전수 크롤. AI 크롤러 UA 15종 내외 개별 접근 테스트(OAI-SearchBot·ChatGPT-User·GPTBot·Claude-SearchBot·Claude-User·ClaudeBot·PerplexityBot·Perplexity-User·Googlebot·Google-Extended·bingbot·CCBot·Yeti 등). CDN/WAF 차단 확인. IP 단위 차단은 서버 로그 없이는 미확인으로 표기 |
| 렌더링 | JS 실행 없이 HTML만으로 본문·JSON-LD 취득 가능한가(SSR) |
| 스키마 | 적용률(전체 상세 페이지 중 적용 수), @graph·@id 참조 구조, Product(offers.price·priceValidUntil·availability·itemCondition·seller·sku·gtin13·mpn·productID), aggregateRating·Review(author·reviewRating), FAQ·HowTo, Organization·sameAs |
| 정합성 | JSON-LD 가격 vs 실판매가, 리뷰 수 vs 실제, 화면 미표시 값(가격·리뷰수·수치·FAQ 전문) |
| 온페이지 | `<title>` 고유성(전 페이지 동일 여부), h1 상품명 포함, h2 개수, meta description 중복, img alt, 본문 이스케이프 오류 |
| 국제화 | hreflang, canonical(/m/ ↔ /web/), content-language 헤더 vs 실제 언어 |
| AI 파일 | llms.txt / llms-full.txt 존재 |
| 등록 | GSC·Bing Webmaster·네이버 서치어드바이저 소유권 |
| 콘텐츠 형식 | 지식 콘텐츠가 영상 중심인지, 텍스트 버전 존재 여부 |

결과는 PASS(잘 되어 있는 것) / FIX(우선순위 HIGH·MID·LOW) 두 축으로 정리하고, FIX 항목이 어떤 엔진의 결과와 직접 연결되는지 적는다(예: 가격 불일치·식별자 부재 → ChatGPT 0%).

## 6단계. 재해석

측정 결과만 보면 "제품 경쟁력 부족"으로 오독될 수 있다. 다음을 확인한다.
1. 측정 영역이 사이트의 **실제 자산**과 맞는가? (연구 조직·논문·특허·전문의 콘텐츠·의료기기 라인 등 지식 자산이 있는데 제품 추천 질문만 측정했는가)
2. 지식 질문에서 누가 답을 차지하는가? (의료기관·학술 문헌·포털이면 그 자리가 목표 시장)
3. 두 사이트(브랜드 사이트 vs 커머스몰)를 AI가 이미 다르게 쓰고 있는가? 같은 처방을 두 사이트에 적용하면 충돌하는가? (판매 안 하는 사이트에 가격·재고 신호를 넣으면 커머스몰과 불일치)
4. 사이트별 성과 기준 분리: 브랜드 사이트 = "AI가 정확히 설명하는가", 커머스몰 = "추천 목록·구매 경로에 오르는가".
5. 다음 실험 대상 정의: 기존에 유효했던 방식(예: 상품 스키마)을 지식 콘텐츠에 확장.

## 7단계. 한계 명시 (보고서 필수 섹션)

- 단일 회차·표본 수 (예: 40건은 경향 수준, 인과 확정에는 반복 측정 필요)
- 응답 변동성 (동일 조건 재측정 변동 폭)
- 인용 산출 엔진 범위
- 브랜드명 매칭 집계의 누락
- 측정 대상 범위(외부 판매 채널 포함 여부)
- 자동 측정 도구 한계(미수집·URL 병합이 정상 수치로 기록됨) → 원문 대조 검증 수행 여부
- 확인 못한 항목(서버 로그 필요 사항 등)

## 보고서 구조 (17p 기준 사례)

표지 → 한 장 요약(KPI 카드 4개 + PASS/FIX/NEXT) → 회사 소개 → 차별점 → 측정 방법 → 진단 결론(탐색 vs 확인 단계 대조) → 응답 원문 2p → 엔진별 특성 → 두 경로 → 페이지 간 격차 → 인용 출처 분석 → 기술 진단 → 두 사이트 관찰 → 재해석 → 측정×전략 → Contact.

작성 원칙: 실제 확인된 데이터만 기재, 추측성 해석 배제. 헤드라인은 단정형 한 문장. 모든 판단은 원문에서 도출. 한계는 별도 표기.
